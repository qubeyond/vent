# Thought Dump — план проекта

## Идея

Веб-приложение (мобильное в приоритете) для бесструктурного дампа мыслей: заело что-то в голове — выплеснул текстом (или голосом), забыл. Без расписания, без обязательной ежедневности. LLM автоматически тегирует и раскладывает записи по темам/подтемам. На основе этого строится облако мыслей / граф, из которого можно вытащить рефлексию. Опционально — мини-агент, с которым можно обсудить свою же карту мыслей.

Ключевое ограничение: всегда под рукой (мобильный веб) и нулевое трение на входе, иначе дамп просто не будет происходить.

---

## Ключевые решения

- Периодичность — дамп в любой момент, без расписания и стриков. Почему: ежедневные пуши и стрики создают давление и превращают разгрузку в обязаловку.
- Экран ввода — голый инпут без полей трения перед сохранением. Почему: выбор категории/настроения перед сохранением снижает шанс что запись вообще сделают.
- Тегирование — автоматическое, LLM тегирует и сверяется с уже существующими тегами. Почему: ручное тегирование противоречит цели «вылить и не думать об организации».
- Визуализация MVP — облако тем/тегов со счётчиками. Почему: граф со связями сразу — нет данных чтобы решить что считать связью.
- Метрики рефлексии — топ слов без стоп-слов, топ повторяющихся цитат, фильтр по периоду. Почему: авто-генерация инсайтов от LLM — это навязанная интерпретация, а не рефлексия.
- Мини-агент по графу — отдельный этап после MVP. Почему: делать сразу — ценность самого дампа ещё не подтверждена.
- Импорт файлов — нужен, но не в первой итерации. Почему: делать частью core loop сразу — усложняет MVP до проверки ценности на живых записях.
- Мобильный доступ — обязателен с первой версии. Почему: сначала веб-десктоп — без мобильного доступа не будет дампа в моменте.
- Готовые аналоги — смотрим как референс, делаем своё. Почему: купить/адаптировать существующее — ни один инструмент не даёт нужного сочетания, плюс платные.
- Инфраструктура — реальный бэкенд на Postgres с первой итерации. Почему: прототип на localStorage — упирается в лимиты и требует переписывания при первом расширении.

## Версии

### v0 (статус: в процессе использования)

#### Фичи:
- Мобильный веб
- LLM-based тегирование
- Фильтры
- Статистика; Топ тегов; Облако слов; Повторяющиеся цитаты

#### Отклонено:
- Граф со связями — недостаточно данных
- Импорт файлов — сначала проверить ценность дампа
- Мини-агент — ценность MVP ещё не подтверждена

#### Дополнено:
- (v0.1.0) CI/CD пайплайн, Docker Compose.
- (v0.2.0) Асинхронная очередь фоновых задач. Заведен CHANGELOG.md. Ручной деплой через GitHub Actions
- (v0.2.1) Makefile

#### DoD:
Две недели реального использования.

---

### v1 (статус: не начато)

#### Фичи:
- Массовый импорт md/txt через существующий пайплайн тегирования
- Граф с рёбрами на реальных данных — co-occurrence тегов или косинусная близость эмбеддингов (pgvector уже стоит с v0)
- Redis — первая настоящая задача: очередь для импорта (или таблица `jobs` в Postgres, без нового сервиса)
- Векторный индекс (`ivfflat`/`hnsw`) на эмбеддинги — по мере роста количества записей

#### Отклонено:
- Алгоритм связей заранее — без реальных данных гадание вслепую

#### DoD:
Импорт без блокировки UI на реальном архиве записей; граф — на реальных данных, не на синтетическом примере.

---

### v2 (статус: не начато)

#### Фичи:
- Чат-интерфейс поверх записей/тегов/тем, отвечает на вопросы о паттернах
- Read-only тулы поверх существующей схемы: записи по тегу, топ тегов, семантический поиск (pgvector)
- Redis — вторая задача: кэш агрегатов и/или состояние диалога

#### Отклонено:
- Автогенерация выводов о паттернах без вопроса пользователя — навязанная интерпретация, не рефлексия

#### DoD:
Собираем только если v0/v1 подтвердили, что дамп используется добровольно.
