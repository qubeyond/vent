# Thought Dump — план проекта

## Идея

Веб-приложение (мобильное в приоритете) для бесструктурного дампа мыслей: заело что-то в голове — выплеснул текстом (или голосом), забыл. Без расписания, без обязательной ежедневности. LLM автоматически тегирует и раскладывает записи по темам/подтемам. На основе этого строится облако мыслей / граф, из которого можно вытащить рефлексию: о чём думал в период X, какие темы навязчивые, топ слов, топ повторяющихся цитат. Опционально — мини-агент, с которым можно обсудить свою же карту мыслей.

Ключевое ограничение: должно быть **всегда под рукой** (мобильный веб) и **нулевого трения** на входе, иначе дамп просто не будет происходить.

---

## Ключевые решения

| Вопрос | Что делаем | Что отклонили и почему |
|---|---|---|
| Периодичность записи | Дамп в любой момент, без расписания, без streak/напоминаний | Ежедневные пуши/стрики как в обычных дневниковых апп — они создают давление и превращают «выплеснул и забыл» в обязаловку, что убивает саму идею |
| Экран ввода | Голый инпут, открылся — сразу можно писать, отправил — готово | Выбор категории/настроения перед сохранением на входе — любое поле трения в момент, когда человек хочет разгрузить голову, снижает шанс, что он вообще запишет |
| Тегирование | Автоматическое, LLM тегирует и раскладывает по темам сразу при сохранении записи, сверяясь с уже существующими тегами (чтобы не плодить дубли типа «мысль»/«мысли») | Ручное тегирование — прямо противоречит цели «просто вылить и не думать об организации» |
| Визуализация на MVP | Облако тем/тегов со счётчиками, без графа со связями | Полноценный граф со связями (как в Obsidian) — на момент старта нет ясного алгоритма, что считать «связью» (совпадение тегов? эмбеддинги? co-occurrence?). Придумывать это до появления реальных данных — гадание вслепую, откладываем на P1 |
| Метрики рефлексии | Топ слов (без стоп-слов/предлогов), топ повторяющихся цитат/тем, фильтр по периоду времени | Автоматическая генерация «инсайтов» от LLM («вот что это значит про тебя») — не просили, это не рефлексия, а навязанная интерпретация |
| Мини-агент по графу | Заложить в план как P2, отдельно от MVP | Делать сразу — самая сложная и необязательная часть, нет смысла тащить её в MVP до того, как подтвердится ценность самого дампа |
| Импорт файлов (md/txt) | Нужен обязательно, но не в первой итерации | Делать частью core loop с самого начала — усложняет MVP, а ценность дампа надо сначала проверить на живых записях, импорт — это добавление исторических данных поверх уже рабочей системы |
| Мобильный доступ | Обязательное требование с первой версии | Отложить на потом ("сначала веб-десктоп") — без мобильного доступа человек физически не будет дампить в моменте, вся идея держится на "всегда под рукой" |
| Готовые аналоги (InfraNodus, Mindsera, Clarido, MindMap Me AI, Obsidian + AI-теггер плагины) | Смотрим как референс, но делаем своё | Купить/приспособить существующее — ни один инструмент не сочетает: (а) фрикшн-фри мобильный дамп, (б) авто-метрики навязчивости/цитат, (в) опциональный агент-собеседник по своим же мыслям. Плюс платные — а платить не хочется |
| Глубина инфраструктуры | Строим на реальном бэкенде (Postgres) с первой итерации, не на "игрушечном" сторадже | Быстрый прототип на localStorage/artifact-storage — годится для 10-минутного демо, но упирается в лимиты (5 МБ на ключ, только текст, никакого relational/vector-поиска) и потребует полного переписывания на первом же расширении — а расширение точно будет (граф, эмбеддинги) |

## Фазы: что делаем и насколько глубоко

### P0 — Захват + автотеги + облако тем

**Фичи:**
- Дамп-инпут (мобильный веб, текст, опционально голос → текст)
- Синхронный вызов LLM на сохранение записи: тегирует, определяет тему/подтему, вытаскивает «цитируемый» фрагмент если есть
- Вид: облако тем/тегов со счётчиками, клик по теме → список записей
- Фильтр по датам
- Топ слов (стоп-слова исключены)
- Топ повторяющихся тем/цитат

**Инфраструктура — делаем сразу по-взрослому, но без лишнего:**

- **Postgres — да, с первого дня.** Не SQLite, не JSON-файлы. Схема дешёвая в настройке, а миграция с файлового хранилища на реляционку — то самое «потом всё переделывать», которого хочешь избежать.
- **pgvector — включить расширение сразу**, даже если P0 векторами ещё не пользуется. Это ничего не стоит на старте, но экономит миграцию в P1, когда понадобятся эмбеддинги для графа.
- Примерная схема:
  - `entries(id, created_at, raw_text, source)` — raw_text никогда не редактируется автоматически
  - `tags(id, canonical_name)`
  - `entry_tags(entry_id, tag_id, confidence)`
  - `embedding` колонка (vector) в `entries` — зарезервирована, не используется до P1
- **Redis — НЕ поднимаем на этом шаге.** Не потому что сложно (согласен, 30 минут), а потому что ему пока нечего делать: при личном использовании с частотой «несколько записей в день» нет очереди, нет кэша, который надо инвалидировать, нет сессий для кэширования. Лишний работающий сервис без задачи — это не «сделали на будущее», это просто лишняя точка отказа, которую придётся поддерживать. Вводим Redis ровно тогда, когда появляется конкретная задача под него (см. P1 и P2 ниже).
- Хостинг: managed Postgres (Neon/Supabase free tier) + простое приложение (Next.js/Express) на Vercel/Fly.io/Railway — или Docker Compose с Postgres, если хочешьself-host. Это дело вкуса, не архитектурный риск.
- LLM-вызов — один серверный эндпоинт: принял raw_text → вызвал Claude API → вернул теги/тему/цитату → записал. Синхронно, по одной записи, без очередей.

**Definition of done:** две недели реального использования с телефона по импульсу, без потери данных, можно вытащить топ тем/цитат за период.

### P1 — Импорт файлов + граф со связями

**Фичи:**
- Массовый импорт md/txt через тот же пайплайн тегирования
- Полноценный граф с рёбрами — теперь на реальных данных решаем, что считать связью:
  - вариант подешевле: co-occurrence тегов в одной записи (без ML, чистый SQL)
  - вариант точнее: косинусная близость эмбеддингов (pgvector уже стоит с P0 — просто считаем эмбеддинг на запись и кладём в уже существующую колонку)

**Инфраструктура:**

- **Здесь Redis впервые получает реальную задачу.** Массовый импорт (десятки-сотни файлов разом) не должен блокировать UI — это первая точка, где нужна асинхронная обработка. Два варианта:
  - Простая очередь на самом Postgres (таблица `jobs`, поллинг) — ноль новой инфраструктуры, для одного пользователя более чем достаточно
  - Redis + BullMQ — раз уж поднять недорого и хочется «сделать по-взрослому сразу», это разумная точка, чтобы завести Redis, потому что задача (очередь фоновых джобов) настоящая, а не придуманная под инфраструктуру
- Векторный индекс (`ivfflat`/`hnsw` в pgvector) на колонку эмбеддингов — добавляется по мере роста количества записей, не раньше.

### P2 — Мини-агент по графу

**Фичи:**
- Чат-интерфейс, агент читает структурированные данные (записи/теги/темы), отвечает на вопросы о паттернах («что меня раздражает в последнее время», «топ идей за месяц»)

**Инфраструктура:**

- Агенту нужен инструментальный доступ к тем же Postgres-данным: `get_entries_by_tag`, `get_top_tags`, `semantic_search` (через pgvector) — по сути маленький набор read-only тулов поверх уже существующей схемы. Новый датастор не нужен.
- **Вторая настоящая задача для Redis:** кэш агрегатов (топ тегов/слов, чтобы не пересчитывать на каждое сообщение) и/или хранение состояния диалога отдельно от основных данных. Если Redis не был поднят на P1 — вот второй естественный повод.
- Явно опциональная фаза: собираем только если P0/P1 подтвердили, что дамп реально используется добровольно.

---

## Anti-scope-creep правило

Не трогать код ради новой фичи, пока не накопилась минимум неделя реального использования текущей версии. Список P0 выше — заморожен с этого момента.

## Бэклог после v0.1.0 (по итогам первого реального использования)

1. **Очередь фоновых задач — супер критично.** Сейчас создание записи — это один блокирующий HTTP-запрос: сохранение + тегирование (+ опциональная LLM-правка текста) происходят синхронно внутри одного запроса. Если закрыть вкладку/потерять связь на телефоне до того, как запрос отработает — результат непредсказуем. Нужна асинхронная обработка: запись сохраняется сразу, тегирование идёт фоновой джобой независимо от того, жив ли ещё клиент; фронт может уйти со страницы и вернуться позже, обработка не прерывается.
2. **Баг: пустое облако (0 записей) ломает страницу на телефоне.** Нужно воспроизвести на реальном устройстве и починить — в песочнице без браузера это не проверить, чинить по факту репорта.
3. **Ввод даты текстом на мобилке** — в фильтре по датам добавить возможность просто вписать дату текстом, не только через нативный date-picker.
4. **Мобильная вёрстка:** кнопка «Создать» — по центру экрана; тумблер (переключатель) — крупнее, чтобы было удобно попадать пальцем.
5. **Тегирование: «быт» стал новым «другое».** После того как научили модель сваливать разовые бытовые дела в тег «быт» вместо отдельных узких тегов, сам «быт» превратился в новый общий бакет-помойку — та же проблема, что раньше была с «другое», просто под другим именем. Нужно доработать подход к раздаче тегов в целом, не точечно патчить один тег.
